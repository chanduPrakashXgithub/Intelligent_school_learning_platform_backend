# F0.6 — Common Response and Error Handling

## 1. Task ID and Task Name
- **Task ID**: `F0.6`
- **Task Name**: Common Response and Error Handling

## 2. Objective
Implement a uniform API response envelope across all endpoints, a standardized application error class hierarchy, unique request tracing (`X-Request-ID`), and a centralized Express error interceptor that guarantees zero internal server error stack traces leak to clients.

## 3. Why This Task Is Necessary
Inconsistent API responses force frontend clients to write brittle, custom parsing logic for every endpoint. Furthermore, unhandled runtime errors can expose sensitive technical details (such as database query strings, file paths, or credentials). A centralized error handler enforces security and provides predictable client contracts.

## 4. Architecture and Implementation Approach
- **Response Wrapper**: `ApiResponse.success(res, data, meta, statusCode)` encapsulates all successful output into `{ success: true, data, meta: { ...meta, requestId }, error: null }`.
- **Request Tracing**: `requestIdMiddleware` generates a UUIDv4 on every request, binds it to `res.locals.requestId`, and sets the HTTP response header `X-Request-ID`.
- **Error Class Hierarchy**: Derived from `AppError extends Error`:
  - `NotFoundError` (404, `NOT_FOUND`)
  - `ValidationError` (400, `VALIDATION_ERROR`)
  - `UnauthorizedError` (401, `UNAUTHORIZED` / `AUTH_*`)
  - `ForbiddenError` (403, `FORBIDDEN` / `ROLE_*` / `CLIENT_TENANT_OVERRIDE`)
  - `ConflictError` (409, `CONFLICT`)
- **Centralized Interceptor**: `errorHandler` catches all thrown errors, maps operational errors to their status codes, handles JSON parser syntax errors, logs 500 errors internally, and responds with a sanitized error envelope.

## 6. Explanation of Important Functions and Components
- `ApiResponse.success(res, data, meta, statusCode)`: Returns standardized JSON payload.
- `requestIdMiddleware(req, res, next)`: Uses `crypto.randomUUID()` for correlation tracking.
- `AppError`: Base class setting `isOperational = true`, `statusCode`, `code`, and `details`.
- `errorHandler(err, req, res, next)`:
  - If headers sent, delegates to default Express handler.
  - If `err` is a body-parser `SyntaxError` (malformed JSON), returns HTTP 400 with code `INVALID_JSON`.
  - If `isOperational`, extracts status, code, message, and details.
  - If unhandled (non-operational), logs error stack trace on the server, but returns safe HTTP 500 with message `"Internal server error"`.

## 7. Execution Flow
```
Incoming Request ➔ requestIdMiddleware (Injects UUIDv4)
Controller / Service throws AppError(statusCode, code, message)
   │
   ▼
Central errorHandler Intercepts Error
   │
   ├─► Log warning (if < 500) or error stack trace (if >= 500)
   │
   ▼
res.status(code).json({
    success: false,
    data: null,
    meta: { requestId },
    error: { code, message, details }
})
```
