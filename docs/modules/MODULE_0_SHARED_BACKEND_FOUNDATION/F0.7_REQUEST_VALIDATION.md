# F0.7 — Request Validation

## 1. Task ID and Task Name
- **Task ID**: `F0.7`
- **Task Name**: Request Validation

## 2. Objective
Implement reusable schema validation middleware using Zod that parses and validates incoming HTTP `body`, `query`, and `params` before payloads reach controller handlers.

## 3. Why This Task Is Necessary
Client requests can contain missing parameters, incorrect data types, malicious injections, or unexpected fields. Validating and sanitizing inputs at the application perimeter prevents unexpected crashes, protects database queries, and provides immediate, actionable feedback to users.

## 4. Architecture and Implementation Approach
- **Higher-Order Middleware**: `validate(schema)` accepts a Zod schema validating a composite object `{ body, query, params }`.
- **Safe Parsing**: Invokes `schema.safeParse(payload)`.
- **Safe Payload Normalization**: In HTTP GET and DELETE requests, incoming request bodies are naturally `undefined`. The middleware normalizes payloads via `{ body: req.body ?? {}, query: req.query ?? {}, params: req.params ?? {} }` so schemas expecting empty objects validate seamlessly.
- **Strict Parsing**: Module schemas enforce `.strict()` on objects to reject unexpected or unknown keys (e.g. injected tenant overrides).
- **Separation of Validated Data**: Sanitized and type-coerced data is attached to `req.validated` for downstream controller consumption.

## 6. Explanation of Important Functions and Components
- `validate(schema)`: The middleware generator function.
- `payload`: Normalizes `req.body`, `req.query`, and `req.params`.
- `result.error.issues.map(...)`: Extracts `{ field, message }` for every failed validation rule.
- `ValidationError`: Thrown when validation fails, resulting in an HTTP 400 response with detailed issue breakdowns.

## 7. Execution Flow
```
Incoming Request ➔ validate(schema)
   │
   ├─► safeParse({ body: req.body ?? {}, query: req.query ?? {}, params: req.params ?? {} })
   │
   ├─► Failure: next(new ValidationError("Invalid request data", details)) ➔ 400 Response
   │
   └─► Success: req.validated = result.data ➔ next() ➔ Controller
```

## 11. Security Considerations
- `.strict()` prevents mass assignment vulnerabilities where attackers inject hidden attributes (e.g. `role: "ADMIN"` or `schoolId: "999"`).
- Automatically trims string inputs where configured in schemas.
