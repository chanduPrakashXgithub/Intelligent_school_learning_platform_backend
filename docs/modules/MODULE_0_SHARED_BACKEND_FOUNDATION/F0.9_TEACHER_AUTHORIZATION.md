# F0.9 — Teacher Authorization

## 1. Task ID and Task Name
- **Task ID**: `F0.9`
- **Task Name**: Teacher Authorization

## 2. Objective
Implement Role-Based Access Control (RBAC) and Attribute-Based Access Control (ABAC) ensuring teachers cannot access administrative endpoints, students cannot access teacher resources, and teachers can only view or manage sections where an active teaching assignment exists.

## 3. Why This Task Is Necessary
Authentication identifies who the user is; authorization determines what they are permitted to do. In an educational platform, student privacy and grading integrity require that a teacher cannot modify lesson schedules or view rosters for classes they do not actively teach.

## 4. Architecture and Implementation Approach
- **RBAC**: `authorizeRole(...allowedRoles)` middleware checks whether `req.user.role` is present in the permitted role list.
- **ABAC (Teaching Scope)**: `requireTeacherSectionAssignment` middleware intercepts section-level routes (`/sections/:sectionId/*`). If the user is a `TEACHER`, it queries `teacher_assignments` to verify that `req.user.teacherId` is assigned to `sectionId` in `req.context.schoolId`.
- **Admin Delegation**: Users with `SCHOOL_ADMIN` role automatically bypass section assignment checks to allow administrative oversight.
- **Date-Bounded Assignments**: Verifies that the assignment is active (`is_active = 1`) and within current date boundaries (`(start_date IS NULL OR start_date <= CURRENT_DATE) AND (end_date IS NULL OR end_date >= CURRENT_DATE)`).

## 6. Explanation of Important Functions and Components
- `authorizeRole(...allowedRoles)`: Returns an Express middleware comparing `req.user.role` against `allowedRoles`. Throws `ForbiddenError("You do not have permission to access this resource", "ROLE_ACCESS_DENIED")` on mismatch.
- `createTeacherSectionAssignmentMiddleware(query, sectionParam)`: Higher-order factory function enabling dependency injection of database query functions for unit testing.
- `requireTeacherSectionAssignment`: Default middleware instance querying `teacher_assignments`.

## 7. Execution Flow
```
Incoming Request ➔ authenticate ➔ tenantContext
   │
   ▼
authorizeRole('TEACHER') ──► If role !== 'TEACHER': throw ForbiddenError(403)
   │
   ▼
requireTeacherSectionAssignment
   │
   ├─► If role === 'SCHOOL_ADMIN': next() (Bypass)
   │
   ├─► Query teacher_assignments:
   │   WHERE school_id = ? AND teacher_id = ? AND section_id = ? AND is_active = 1
   │
   ├─► If 0 rows: throw ForbiddenError(403, "SECTION_ASSIGNMENT_REQUIRED")
   │
   └─► If row exists: next() ➔ Proceed to Controller
```

## 8. Database Interaction
Executes indexed lookups on `teacher_assignments` using the composite index `idx_teacher_assignment_lookup (school_id, teacher_id, section_id, is_active)`.

## 9. API Endpoints
- `GET /api/v1/classes/sections/:sectionId`: Demonstrates enforced role and teacher section assignment protection.

## 11. Security Considerations
- Prevents cross-teacher tampering: Teacher Priya cannot grade, schedule, or view Section 8B if assigned only to Section 8A.
- Parameterized queries prevent SQL injection through route parameters.
