# F0.10 — School-Level Data Isolation

## 1. Task ID and Task Name
- **Task ID**: `F0.10`
- **Task Name**: School-Level Data Isolation

## 2. Objective
Enforce strict server-authoritative school tenancy, ensuring that data belonging to School A is completely inaccessible to users belonging to School B, and client-supplied tenant identifiers are detected and rejected.

## 3. Why This Task Is Necessary
The School Learning Platform is a multi-tenant platform designed to scale across numerous educational institutions. Data leaks between schools would violate student data privacy laws, institutional confidentiality, and educational integrity. Tenancy cannot rely on frontend good behavior.

## 4. Architecture and Implementation Approach
- **Zero-Trust Client Identifiers**: The client is never permitted to dictate `school_id`. Any presence of a `schoolId` or `school_id` parameter in request headers, query parameters, URL path parameters, or request bodies triggers an immediate `403 Forbidden` (`CLIENT_TENANT_OVERRIDE`).
- **Server Context Derivation**: The `tenantContext` middleware extracts `schoolId` strictly from `req.user.schoolId` (populated from the cryptographically verified JWT) and places it into an immutable `req.context.schoolId`.
- **Repository Scoping**: `BaseRepository` methods (`findById`, `findAll`, `count`) mandate `schoolId` as an argument and append `WHERE school_id = ?` to every query.
- **Relational Integrity**: The MySQL database schema enforces compound foreign keys linking child records to parent records within the same `school_id` (`CONSTRAINT fk_sections_class FOREIGN KEY (school_id, class_id) REFERENCES classes(school_id, id)`).

## 6. Explanation of Important Functions and Components
- `tenantContext(req, res, next)`:
  - Ensures `req.user` is present.
  - Calls `hasClientTenantOverride(req)` to deeply scan headers, query, body, and params for any key resembling `"schoolid"` (case-insensitive, ignoring underscores and hyphens).
  - Binds `req.context = Object.freeze({ schoolId })`.
- `BaseRepository`:
  - Enforces `ALLOWED_TABLES` whitelist to protect against dynamic table injection.
  - Enforces numeric regex validation on IDs and school IDs.
  - Appends `AND school_id = ?` to all query builders.

## 7. Execution Flow
```
Client Request ➔ authenticate (resolves req.user.schoolId from JWT)
   │
   ▼
tenantContext Middleware
   │
   ├─► Client passed ?schoolId=X: throw ForbiddenError(403, "CLIENT_TENANT_OVERRIDE")
   │
   └─► Verified: req.context = Object.freeze({ schoolId: req.user.schoolId })
   │
   ▼
Repository Layer: SELECT ... WHERE id = ? AND school_id = ?
   │
   ▼
MySQL Composite Foreign Key Check: (school_id, id)
```

## 8. Database Interaction
All multi-tenant queries bind `req.context.schoolId`. Composite unique keys `UNIQUE (school_id, id)` and composite foreign keys ensure hardware-level isolation.

## 9. API Endpoints
Applies to all tenant-scoped `/api/v1/*` endpoints.

## 10. Dependencies on Other Tasks

## 11. Security Considerations
- Immune to parameter tampering: a teacher from School 1 passing `?schoolId=2` or `{ "schoolId": 2 }` receives an immediate 403 error.
- Horizontal privilege escalation across schools is physically impossible.
