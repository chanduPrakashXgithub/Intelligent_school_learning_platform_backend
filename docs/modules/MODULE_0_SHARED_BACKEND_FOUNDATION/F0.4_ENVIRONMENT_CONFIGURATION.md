# F0.4 — Environment Configuration

## 1. Task ID and Task Name
- **Task ID**: `F0.4`
- **Task Name**: Environment Configuration

## 2. Objective
Establish a centralized, immutable, and fail-fast environment configuration module using Zod schema validation to ensure the backend never starts with missing, invalid, or insecure settings.

## 3. Why This Task Is Necessary
Misconfigured environments (such as an empty database password, malformed port, or missing JWT secret) can cause silent failures, security vulnerabilities, or unpredictable crashes during production runtime. Validating configuration at boot guarantees system integrity.

## 4. Architecture and Implementation Approach
- **Declarative Schema**: Uses Zod to define data types, port ranges (1–65535), default fallbacks, and minimum length requirements for secrets.
- **Fail-Fast Boot**: The configuration module parses `process.env` immediately upon import. If validation fails, it outputs field-level error messages and halts process startup via `process.exit(1)`.
- **Immutable Export**: The resulting configuration object is frozen via `Object.freeze()` to prevent runtime tampering.

## 6. Explanation of Important Functions and Components
- `envSchema`: Zod schema specifying:
  - `NODE_ENV`: enum `['development', 'production', 'test']`
  - `PORT`: coerced integer (1–65535, default 5000)
  - `CORS_ORIGINS`: comma-separated string parsed into an array
  - `DB_HOST`, `DB_PORT`, `DB_USER`, `DB_PASSWORD`, `DB_NAME`: database connection attributes
  - `JWT_SECRET`: minimum 32-character string
  - `JWT_EXPIRES_IN`: token duration string (default "15m")
- `env`: The exported immutable configuration object.
- `databaseConfig`: Scoped configuration object consumed by the database pool.
- `constants.js`: System-wide enums (`USER_ROLES`, `HTTP_STATUS`, `API_PREFIX`).

## 11. Security Considerations
- Enforces a minimum 32-character length for `JWT_SECRET` to prevent brute-force signature attacks.
- Rejects invalid characters and out-of-range ports.
- Sensitive environment variables are kept in `.env` (git-ignored) and never committed to version control.
