# F0.3 — MySQL Connection and Connection Pooling

## 1. Task ID and Task Name
- **Task ID**: `F0.3`
- **Task Name**: MySQL Connection and Connection Pooling

## 2. Objective
Establish a production-grade database access layer connecting to MySQL 8.4 Server using `mysql2/promise` with connection pooling, parameterized query execution, atomic transaction boundaries, and guaranteed connection leak prevention.

## 3. Why This Task Is Necessary
Opening individual database connections per request is resource-intensive and prone to exhaustion under load. A managed connection pool maintains reusable persistent connections. Furthermore, complex academic operations (e.g., publishing lesson versions, scheduling assessments) require atomic transactions that guarantee complete rollback if any step fails.

## 4. Architecture and Implementation Approach
- **Pool Singleton**: Created via `mysql.createPool()` in [src/core/database/pool.js](file:///E:/School_Learning_platform/backend/src/core/database/pool.js).
- **Settings**: Configured with `connectionLimit: 10`, `waitForConnections: true`, `queueLimit: 0`, and `enableKeepAlive: true`.
- **Prepared Statements**: `executeQuery` and `executeMutation` use `pool.execute(sql, params)` to execute server-side prepared statements, eliminating SQL injection.
- **Unit of Work**: `withTransaction(callback)` encapsulates `beginTransaction()`, execution, `commit()`, and automated `rollback()` upon error, with connection release in the `finally` block.

## 6. Explanation of Important Functions and Components
- `pool`: The shared MySQL2 pool instance.
- `checkDatabaseConnection()`: Acquires a connection from the pool and issues a `ping()`, returning true on success and always releasing the connection.
- `executeQuery(sql, params)`: Executes a `SELECT` query and returns the rows array.
- `executeMutation(sql, params)`: Executes an `INSERT`, `UPDATE`, or `DELETE` query, returning `{ affectedRows, insertId, changedRows }`.
- `withTransaction(callback)`: Manages connection acquisition, transactional state tracking (`transactionStarted`), rollback handling, and guaranteed cleanup.
- `closeDatabasePool()`: Drains the pool gracefully during server shutdown.

## 7. Execution Flow
```
withTransaction(callback)
   │
   ├─► pool.getConnection()
   ├─► connection.beginTransaction()
   ├─► callback(connection) ──► Operations succeed
   │                                  │
   │                                  ▼
   │                           connection.commit()
   │
   └─► On Error: connection.rollback() ➔ Re-throw original error
   │
   ▼
finally: connection.release() (ALWAYS executed)
```

## 8. Database Interaction
Directly communicates with MySQL 8.4 Server on `localhost:3306`, executing InnoDB queries and transaction commands.

## 11. Security Considerations
- Parameterized SQL prepared statements ensure untrusted client inputs are never concatenated directly into SQL strings.
- Numeric identifier validation is enforced before execution.
- Connection credentials are loaded securely from `.env` and never logged.
